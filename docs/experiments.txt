# Objetivo

Quero reproduzir o experimento descrito no artigo **MCPTox**:

* Paper: https://arxiv.org/pdf/2508.14925
* Repositório oficial: https://github.com/zhiqiangwang4/MCPTox-Benchmark

A reprodução não precisa ser idêntica ao ambiente dos autores. O objetivo é reproduzir a metodologia utilizando um **Envoy AI Gateway** e um **MCP Server Wrapper** executando em Kubernetes.

# Contexto

Assuma que:

* Estou utilizando Kubernetes.
* Já existe um Envoy AI Gateway funcional.
* O Gateway já está configurado para acessar os modelos disponíveis.
* O MCP Server Wrapper será anexado (attached) ao Envoy AI Gateway para disponibilizar as ferramentas (tools).

O objetivo do experimento é verificar se as LLMs chamam ferramentas envenenadas (poisoned tools), seguindo a metodologia apresentada no artigo.

---

# Modelos disponíveis

Atualmente possuo apenas os seguintes modelos, ambos presentes no artigo:

* gpt-4o-mini
* gemini-2.5-flash

Considere esse subconjunto suficiente para uma reprodução mínima do experimento.

---

# Requisitos do MCP Wrapper

O MCP Wrapper deve:

* ser implementado em Python;
* expor as tools utilizando o protocolo MCP;
* carregar automaticamente as ferramentas envenenadas durante o deployment;
* preferencialmente utilizar ConfigMap para fornecer as definições das tools;
* ser executado em Kubernetes.

A implementação pode ser organizada de uma das seguintes formas:

1. Deployment + ConfigMap contendo as tools envenenadas; ou
2. Um container que recebe as tools via ConfigMap durante a inicialização.

Prefira a abordagem mais simples e de fácil manutenção.

---

# Requisitos do experimento

Desenvolver um script responsável por executar todo o experimento.

O script deverá:

1. Ler automaticamente as ferramentas envenenadas localizadas em:

```
MCPTox-Benchmark/def_tool/
```

2. Criar (ou atualizar) o MCP Wrapper utilizando essas ferramentas.

3. Publicar o MCP Wrapper no Kubernetes.

4. Conectar o MCP Wrapper ao Envoy AI Gateway.

5. Executar os testes seguindo a metodologia utilizada no notebook:

```
MCPTox-Benchmark/analysis.ipynb
```

6. Utilizar também:

```
MCPTox-Benchmark/pure_tool.json
```

para gerar as perguntas enviadas às LLMs e posteriormente verificar se a ferramenta envenenada foi chamada, reproduzindo a lógica do benchmark original.

7. Coletar os resultados de todos os testes.

8. Gerar um relatório consolidado contendo, pelo menos:

* modelo utilizado;
* tool utilizada;
* prompt enviado;
* resposta da LLM;
* se a poisoned tool foi chamada;
* resultado final (sucesso/falha da injeção).
